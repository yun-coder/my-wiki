# AI 知识精华总览

> 从 01–14 专题、09/10 自动主库和 99-归档提炼出的快速阅读版。项目链接保留在专题和主库中；本页只保留判断、方法和选型入口。

## 一、AI 应用的完整结构

```text
模型与数据 → 推理部署 → Agent 编排 → 工具/MCP → RAG/记忆
          → 业务工作流 → 评测/观测/安全 → 持续运营
```

核心判断：AI 项目不能只看模型效果。真正可用的系统还要解决上下文、工具权限、成本、失败恢复、结果验证和数据隐私。

## 三、模型与平台

- **通用模型**：比较推理、代码、长上下文、多模态、价格、延迟和可用性，不固定永久排名。
- **本地模型**：Ollama 适合个人试用，llama.cpp 适合轻量和边缘部署，vLLM 适合服务化并发。
- **模型选择**：先按任务建立测试集，再比较质量、成本和失败类型；不要只看榜单或宣传 Demo。
- **网关策略**：聚合平台适合快速切换模型；关键业务要保留直连和降级路径，避免单一供应商锁定。

详见：[AI 大模型平台](../03-AI大模型平台.md)、[AI 模型与工具评估](../12-AI模型与工具评估.md)。

## 四、Agent、Skills 与工具

- Agent = 模型 + 状态 + 工具 + 目标 + 执行循环 + 结果验证。
- Skill 应该描述触发条件、输入输出、权限边界、失败处理和验证方式，而不只是 Prompt。
- MCP 适合统一接入外部工具和数据；工具应最小权限、可审计、可撤销。
- 多 Agent 适合角色分工、并行研究和独立审查；协调成本高时应退回单 Agent。
- 长任务需要持久状态、断点恢复、任务锁、预算硬停止和人工审批。

代表入口：[AI 智能体与技能](../02-AI智能体与技能.md)、[AI 开源项目全景地图](../14-AI开源项目全景地图.md)。

## 五、RAG 与长期记忆

RAG 解决“从外部资料检索上下文”，记忆解决“跨会话保留事实、偏好和经验”，两者不是同一件事。

一个可用的知识库至少需要：

1. 文档解析和结构保留：标题、表格、图片、页码和来源。
2. 召回与重排：关键词、向量、混合检索和权限过滤。
3. 引用与可验证性：回答能回到原文，支持反馈和纠错。
4. 更新与生命周期：过期、冲突、删除和版本回滚。
5. 评测：召回率、引用准确率、答案正确性、延迟和成本。

代表项目：RAGFlow、LlamaIndex、GraphRAG、Qdrant、Milvus、pgvector、Hindsight、Mem0。

## 六、内容生成与多模态

- **视频**：重点不是单次生成，而是角色一致性、镜头控制、音画同步、批量生产和版权管理。
- **图像**：ComfyUI/Diffusers 适合工作流和可控生成；ControlNet、分割和检测模型负责结构控制。
- **语音**：Whisper/faster-whisper 负责识别；Piper、GPT-SoVITS、VoiceStudio 负责本地合成或克隆。
- **文档**：Docling、MinerU、MarkItDown、PaddleOCR 把 PDF、Office、图片变成可检索结构。
- **Office**：Univer 适合把表格、文档和演示能力嵌入自己的产品或 Agent。

详见：[AI 视频生成](../01-AI视频生成.md)、[AI 工具与产品](../04-AI工具与产品.md)。

## 七、GEO 与增长营销

GEO 不是 SEO 的替代品，而是在 SEO 的可抓取性和权威性基础上，提高内容被 AI 理解和引用的概率。

- 内容采用答案优先、短段落、清晰层级、列表和表格。
- 展示作者、组织、产品等实体；使用结构化数据描述关系。
- 提供原创数据、案例、专家引用和可验证来源。
- 同时经营官网、行业媒体、社区、评测和用户评价中的实体一致性。
- 指标从排名/点击扩展到引用率、提及率、答案位置和事实一致性。

详见：[GEO 与增长营销](../11-GEO与增长营销.md)。

## 八、外贸与业务自动化

外贸数字化的核心不是单点工具，而是：

```text
市场研究 → 内容/获客 → 线索进入 CRM → 报价与跟进
        → 订单/单证 → 交付 → 客户维护与复购
```

优先自动化高频、规则明确、可审计的环节；涉及价格、合同、付款和合规的环节保留人工确认。

详见：[外贸数字化](../05-外贸数字化.md)。

## 九、前端与产品实现

- React/Vue 负责应用层，Tailwind、Ant Design、Element Plus 等负责组件和交互效率。
- AI 产品前端重点是流式输出、任务状态、引用来源、错误恢复、权限提示和可编辑结果。
- 复杂工作流应把状态机、事件和后台任务与 UI 解耦，避免把 Agent 循环写进页面组件。
- 可视化和数据密集型页面优先保证信息层级、响应速度和可追踪操作。

详见：[前端开发资源](../06-前端开发资源.md)。

## 十、评测、安全与运营

上线前至少建立四类检查：

- **质量**：固定样本、成功标准、回归集和人工抽检。
- **成本**：按用户、任务、模型统计 Token、延迟和失败重试。
- **安全**：最小权限、敏感信息过滤、沙箱、工具审批和审计日志。
- **可靠性**：超时、重试、幂等、断点恢复、人工接管和回滚。

代表工具：[Langfuse](https://github.com/langfuse/langfuse)、[Phoenix](https://github.com/Arize-ai/phoenix)、[Ragas](https://github.com/explodinggradients/ragas)、[DeepEval](https://github.com/confident-ai/deepeval)、[Promptfoo](https://github.com/promptfoo/promptfoo)。
