## 1. 一句话定义与边界

**GEO 是在 SEO 的可抓取性与权威性之上，额外优化"内容能否被生成式引擎检索到、抽取成段、作为来源引用、并准确合成进答案"的一层工作；它换取的是答案里的可见性，而不是排名。**

原文定义（§1.1）：GEO 是 SEO 在 AI 时代的演进，目标是让品牌信息成为 AI 生成的答案本身的一部分，而不是在 SERP 里争一个链接位。

| GEO 是 | GEO 不是 |
|---|---|
| 对"检索命中 + 可引用性 + 事实一致性"的持续优化 | 不是 SEO 的替代品；两者互补，SEO 负责被发现，GEO 负责被消化和引用（原文 §1.3） |
| 自有站内容工程 + 站外实体与提及管理（原文 §5） | 不是"刷 AI 回答"：模型输出无法直接编辑，只能通过改变网络上的可信信息源来改变它（原文 §6.4） |
| 零点击环境下重设的 KPI 体系（引用、提及、位置） | 不是纯技术改动：Schema 是基础设施，不替代内容本身 |
| 一份持续复测的流程（词库固定 → 周期复测） | 不是一次性项目，也不是"发一批稿就结束" |

**判定线**：一个页面值得投入 GEO，需同时满足三条——能被爬虫完整取到正文、关键事实可被第三方核验、答案能用 100 字以内说清。缺一条先补基础，不做内容加码。

## 2. 机制：生成式引擎怎么选源

原文 §2.2–2.4 的链路：查询先转向量做语义匹配（不是关键词字面匹配）→ 复杂问题被"查询扇出"拆成子问题分别检索 → 检索结果按权威性与可解析性筛选 → 被选中的片段进入引用列表 → 模型用它们合成连贯答案。

| 环节 | 机器在做什么（原文） | 你能改的变量 | 怎么验证 |
|---|---|---|---|
| 检索 Retrieval | 语义相似度匹配；一个查询扇出成多个子问题（§2.4） | 覆盖子问题；术语与用户问法同构；正文可抓取 | 逐个子问题去问引擎，看是否有我方页面进入候选 |
| 重排 / 筛选 | 优先权威、可信、可解析的来源（§3.1） | E-E-A-T 信号、原创数据、dateModified、结构清晰度 | 同一问题换 3 个引擎，记录被引用的都是什么类型的站 |
| 引用 Citation | 把来源列进答案的引用区（§1.2） | 答案优先段落、FAQ、表格、明确数字与单位 | 抓引用 URL，是否指向我方具体页面而非首页 |
| 合成 Synthesis | 模型改写、拼接、可能失真 | 事实表述唯一化（价格、MOQ、交期、认证只留一种写法） | 抽检答案中的我方事实是否与官网一致 |

原文提到的信息来源远超自然结果前十：深层页面、论坛与评论站、结构化知识库都会进入候选（§2.4）。**这决定了 GEO 不可能只在官网做。**

**为什么"被引用"部分取代"被点击"**：答案是直接在结果页/对话里给出的，用户不必跳转（原文 §1.2 的零点击环境）；且引用往往以折叠的来源列表呈现，点击率天然低于蓝色链接。原文进一步指出，生成式引擎更多服务于已完成初步研究、处于考虑/决策阶段的用户，等于把漏斗倒置（§1.2）——所以 GEO 的第一价值是"在决策时刻与答案绑定"，第二价值才是流量。

## 3. 内容工程

| 要素 | 可执行做法 | 验收标准 |
|---|---|---|
| 答案优先 | 每个页面/每个 H2 下先给 50–100 词的直接答案，再展开证据（原文 §3.2 的"倒金字塔"） | 首 100 字内能独立回答标题问题；删掉后文仍成立 |
| 问题—证据—结论 | 每节固定四段：问题 → 一句结论 → 数据/案例/标准依据 → 边界与例外（什么情况下不适用） | 每节至少 1 个可核验数字或条款，且写明适用范围 |
| 实体与术语一致 | 品牌名、产品型号、单位（mm/kg/FOB/CIF）、认证名（CE/RoHS/ISO 9001）全站唯一写法；公司名地址电话（NAP）跨平台一致（原文 §4.4） | 全站抽查 20 页，命名冲突 = 0 |
| 原创数据 | 一手的价格区间、交期区间、产能、检测项、脱敏案例数字——原文称含统计数据与引用的内容在生成式引擎中可见性更高（§3.4，具体幅度待核，见 §9） | 每个核心页至少 1 组自有一手数据，且能说明取样口径 |
| 作者与组织可信度 | 署名 + 作者页（职位、从业年限、knowsAbout）+ 公司页含联系方式、隐私说明、HTTPS（原文 §3.1 的 E-E-A-T 四项） | 作者页可访问且与 Article 的 author 字段一致 |
| 更新与时效 | 页脚"最后更新"可见；价格/交期/政策季度复核；改版同步更新 dateModified | 抽 10 个核心页，无"两年未更新"的价格页 |
| 语言 | 句子 ≤20 词、段落 2–4 句、对话式表述（原文 §3.3，作为编辑规约而非硬事实） | 编辑走查 1 页通过即可全站套用 |
| 结构化呈现 | 用列表/表格承载对比、参数、步骤；原文引用研究称多数 AI Overviews 含列表（§3.3，数据待核） | 每个核心页至少 1 个表格或编号清单 |

**编辑模板（复制即用）**：`## 问题句` → `一句话结论（含数字）` → `证据（数据 / 标准 / 案例 / 专家引语）` → `不适用的情况` → `FAQ 2–4 条`。

## 4. 技术基础

**可抓取**：先审 `robots.txt`，再决定放谁进来——这是策略题不是技术题。

| 爬虫 | 用途 | 建议 |
|---|---|---|
| Googlebot | 搜索收录、AI Overviews 取源 | 必须放行 |
| OAI-SearchBot / ChatGPT-User | OpenAI 搜索索引 / 用户主动抓取 | 放行（否则不进 ChatGPT 检索源） |
| GPTBot | 模型训练抓取 | 可选；不放行不影响被检索引用 |
| PerplexityBot | Perplexity 索引 | 放行 |
| Google-Extended | 仅控制 Gemini 训练/grounding，**不影响 Google 搜索收录** | 与"AI 抓取"分开决策（原文将其并列论述，属口径不严谨，见 §9） |

**渲染友好**：关键正文用 SSR 或静态 HTML 输出，不依赖客户端 JS（原文 §4.3）；服务器响应时间以 <500ms 为目标（原文引用的相关性观察，非因果结论）。

**结构化数据（JSON-LD）**：原文 §4.2 的五类核心 Schema 与关键属性。

| 类型 | 作用 | 必填/关键属性 |
|---|---|---|
| Organization | 把品牌确立为知识图谱中的实体 | name, url, logo, sameAs（Wikidata/社媒/目录页）, contactPoint |
| Person | 作者身份，专业性信号 | name, jobTitle, worksFor, knowsAbout, sameAs（LinkedIn） |
| Article | 标记内容性质与时效 | headline, author（嵌套 Person）, publisher（嵌套 Organization）, datePublished, dateModified |
| FAQPage | 让问答可被直接抽取 | mainEntity → Question / acceptedAnswer |
| Product / Service | 支撑商业对比类查询 | name, brand, description, aggregateRating, review |

```json
{"@context":"https://schema.org","@type":"Organization",
 "name":"（公司全称，与 NAP 一致）","url":"https://example.com/","logo":"https://example.com/logo.png",
 "sameAs":["https://www.wikidata.org/wiki/Qxxxx","https://www.linkedin.com/company/xxx","（行业目录页）"],
 "contactPoint":{"@type":"ContactPoint","contactType":"sales","email":"sales@example.com","telephone":"+86-..."}}
```

验证： [Rich Results Test](https://search.google.com/test/rich-results) 与 [Schema Markup Validator](https://validator.schema.org/) 双通过；也可用现有页面的 [结构化数据工具](https://www.google.com/webmasters/markup-helper/) 生成初稿。

**站内信息架构**：按"主题簇"组织而非按栏目——产品页 ↔ 对比页 ↔ 价格页 ↔ 行业方案页 ↔ FAQ 互相内链，任意页面 3 次点击内可达；面包屑与 H1/H2/H3 层级唯一。

**站点地图与 IndexNow**：`sitemap.xml` 保留真实 `lastmod`；新增或改版页面通过 [IndexNow](https://www.indexnow.org/zh_cn/documentation) 主动提交，缩短发现延迟；用 [Google Search Console](https://search.google.com/search-console) 核对是否真的被收录（收录是 GEO 的前置条件，不是结果）。

**多语言（外贸必做）**：每种语言独立 URL（`/en/`、`/de/` 或子域），配套 `hreflang` 互指（原文 §9.2）；不要把中英文混在同一页靠 JS 切换。

## 5. 监测与指标

### 5.1 五个指标怎么算

| 指标 | 定义（可直接建表） | 数据来源 |
|---|---|---|
| 被引用率 | 出现"指向我方域名引用"的 query 数 ÷ 目标 query 总数 | 逐条抓引用 URL；工具辅助 |
| 品牌提及率 | 答案正文出现品牌/产品名的 query 占比（含无链接提及，原文 §5.1 视其为权威信号） | 同上，与"被引用"分开记 |
| 答案位置 | 首次提及次序分档：第 1 位 / 前 3 / 仅列末尾 / 未出现（原文 §8.2 的答案定位分数） | 人工或工具打分 |
| 引用页面 | 被引用的具体 URL，按模板归类（产品/对比/价格/方案/FAQ/博客） | 用于反推"哪类模板有效" |
| 事实一致性 | 抽检回答中关于我方的事实（价格、MOQ、交期、认证、产能）：正确 / 缺失 / 错误 | 错误率 >10% 触发更正（改官网、补 FAQ、统一表述） |

配套：**引用质量**（引的是我方页面、竞品页面还是第三方评测）与 **AI 引荐流量**（GA 里按 referrer 过滤 chatgpt.com、perplexity.ai、gemini.google.com 等）。

### 5.2 工具清单（保留现有页面口径，补上"监测什么"）

| 工具 | 监测什么 | 在流程里的位置 |
|---|---|---|
| [GEOBase](https://geo.aibase.com/) | 品牌可见度、AI 搜索监测 | 国内 AI 搜索表现的周度看板 |
| [新榜智汇](https://geo.newrank.cn/) | GEO 效果监测、内容分析 | 品牌与新媒体团队的内容侧复盘 |
| [透镜 GEO](https://geo.timus.cn/) | AI 搜索排名监控 | 快速验证关键词/问题的表现变化 |
| [艾奇 GEO](https://www.27geo.com/) | 品牌推荐、排名监测 | 营销效果跟踪 |
| [Semrush](https://www.semrush.com/seo/) · [AI 可见性](https://www.semrush.com/blog/ai-visibility/) | 关键词与竞品基线；AI 提及/引用追踪 | 建传统搜索基线 + 竞品引用对比 |
| [Ahrefs](https://ahrefs.com/zh/all) | 外链、内容与关键词研究 | 判断哪些第三方来源被引擎信任（来源权威性） |
| [DataForSEO](https://app.dataforseo.com/) | SEO 数据 API | 批量、自动化采集排名与 SERP 数据 |
| [Google Search Console](https://search.google.com/search-console) | 收录、查询、页面表现 | 验证可发现性；曝光作零点击的代理指标 |

**手动审计（无需预算即可跑）**：固定 query 集 → 在 [ChatGPT](https://chatgpt.com/)、[Perplexity](https://www.perplexity.ai/)、[Gemini](https://gemini.google.com/)、Google AI Overviews 上以无痕模式逐条提问（原文 §6.1）→ 每条记录：query、引擎、是否提及、提及语境与情感、引用 URL、对手是否被提及。同一批 query、同一引擎、同一模式，才可比。

**归因的现实做法**：AI 引荐流量 + 品牌搜索量变化 + 直接流量 + 表单里加一题"您如何了解到我们（含 AI 搜索/ChatGPT 选项）"（原文 §8.3）。零点击场景下没有完美归因，只有多重代理指标互相印证。

## 6. 落地 SOP（6 步）

| # | 步骤 | 产出物 | 验收标准 |
|---|---|---|---|
| 1 | 建词库与基线 | query 表：品牌词 / 品类词 / 高意图对比词（`X vs Y`、`best X`）/ 信息型问题（原文 §6.1 四类），30–50 条 | 每条注明目标市场语言与业务价值；同一批 query 全流程不改 |
| 2 | 三方审计 | 页面清单 + 技术清单 + 站外清单 | robots 策略已定；5 类 Schema 校验通过；核心页响应时间已测；已记录当前被引用情况 |
| 3 | 页面改造 | 5 类页模板（产品/对比/价格/方案/FAQ）各 1 个样板 | 首 100 字有答案；FAQ Schema 通过；作者署名与作者页齐全；dateModified 真实 |
| 4 | 站外与实体 | 目录/评测/论坛/媒体提及计划 + 知识面板与 Wikidata 核对（原文 §5、§6.2） | NAP 全平台一致；Organization 的 sameAs 至少 3 个权威第三方 |
| 5 | 监测复测 | 周度记录表 + 月度报告（可见性、引用、事实一致性） | 同一批 query 复测，引用 URL 可回溯到具体页面；错误事实有处理记录 |
| 6 | 模板迭代 | 更新后的模板与写作规约 | 每季度把"被引用最多的 3 个页面"的共同特征写回模板，并复测验证 |

## 7. 常见误区

1. **把 GEO 当 SEO 替代品**。基础技术健康与外链权威仍是前提，砍掉 SEO 做 GEO 会同时丢掉两条通道（原文 §1.3）。
2. **以为能"改掉"AI 的负面答案**。删不掉，只能靠更多高质量正面内容与第三方信源稀释（原文 §6.4）；把精力放在投诉反馈上必然低效。
3. **只上 Schema 不改内容**。结构化数据解决"机器读得懂"，不解决"值得被引用"。
4. **为 AI 而写的模板腔**。堆小标题、堆列表、通篇"总而言之"，没有数字与边界条件，引擎没有可引用的实体信息。
5. **只盯流量，不看引用**。零点击环境下流量下降不等于失败；反之引用数上涨但引的是竞品页面照样是失败（要看引用页面归属）。
6. **单引擎、单次、带个性化地抽样**。一条结果就下结论，且未用无痕模式，样本被登录态与地域污染。
7. **把 AI 生成量当产能**。批量生成不审核会踩"规模化内容滥用"，且破坏事实一致性；原文的 Bankrate 案例强调的是"AI 生成 + 严格人工审核"（§10.1）。
8. **只在官网做**。目录、评测站、论坛、UGC 是引擎的重要来源（原文 §2.4、§5.2），站外缺位等于把引用位让给对手。
9. **事实表述不唯一**。同一 MOQ 在官网、目录、报价单上三个数字，模型只能取其一，错误率必然上升。
10. **一次性项目制**。不复测就没有基线，无法判断改动是否有效，也无法向业务方证明投入。

## 8. 外贸 B2B 与 TradeMind 适配判断

> 前提说明：以下把 TradeMind 的产品线按"Site（独立站/内容与官网底座）+ SDR（获客与销售开发）"理解；若实际边界不同，按 §8.3 把职责重新指派到对应产品即可，判断逻辑不变。

### 8.1 先做哪类页面（按投入产出排序）

| 页面类型 | 为什么值得先做 | 改造要点 | 验收 |
|---|---|---|---|
| 产品页 | 品类词与型号词是最直接的商业查询入口 | 首段给"是什么 + 关键参数 + 适用场景"；参数用表格；补 Product Schema | 任一型号能被单独检索到且参数完整 |
| 对比页（`A vs B`、`替代某品牌`） | 原文的对比类高意图查询正在被 AI 直接回答（§6.1） | 给对照表 + 各自适用场景 + 明确不适用条件；不贬低对手 | 该问题下出现我方页面引用或品牌提及 |
| 价格页 / 报价区间页 | B2B 买家最先问"多少钱"，AI 常因无公开数据而给不出答案 | 给区间 + 影响价格的因素（材质、工艺、量级、认证）+ 询价入口 | 回答中"价格"部分引用我方口径而非编造 |
| 行业方案页 | 把产品映射到具体行业场景（如包装、汽配、建材） | 场景痛点 → 方案 → 案例数字 → 合规要求 | 行业词 query 下有提及 |
| FAQ | 抽取成本最低、性价比最高 | 真实询盘问题整理成 FAQPage；答案 100 词内 | FAQ 结构化校验通过，且被答案引用 |

### 8.2 英文市场 vs 中文市场的差异

| 维度 | 英文市场（欧美为主） | 中文市场 |
|---|---|---|
| 引擎与入口 | Google AI Overviews、ChatGPT、Perplexity、Gemini | 国内 AI 搜索与问答产品；入口更分散、更新更快 |
| 站外信任来源 | 行业目录与软件评测站、Reddit/Quora 讨论、垂直媒体（原文 §5.2） | 知乎、公众号、行业门户、B2B 平台店铺与问答 |
| 权威信号 | 认证与检测报告、第三方评测、协会会员、真实客户评价 | 案例、媒体背书、平台成交与评价、资质证书 |
| 语言细节 | 单位与术语固定（inch/mm、FOB/CIF、MOQ），拼写一致 | 中英混排易造成实体分裂，需统一产品名译法 |
| 多语言结构 | 独立 URL + hreflang，按国家/语言分版 | 简体为主，注意港澳台用词差异 |
| 内容节奏 | 长文 + 数据 + 明确边界，更新可追溯 | 短平快 + 图表 + 结论前置，适配移动端阅读 |

补充（原文 §9.2–9.3）：非英语查询可能被模型内部转成英文检索，因此**高质量英文内容会间接影响非英语市场的表现**；反过来，本地语言的优质内容在低资源语言环境中更稀缺、更容易被当作权威源——对外贸企业，英文内容仍是主干，小语种是差异化机会而非替代。

### 8.3 与 Site / SDR 怎么配合

- **Site 是底座**：SSR 输出、robots 放行检索型爬虫、5 类 Schema、sitemap + IndexNow、hreflang、页面模板（答案优先 + 表格 + FAQ 模块）。GEO 的大多数技术项都落在 Site 的发布流程里，应做成"上线即合规"的模板约束，而非事后补丁。
- **SDR 是承接与验证**：引用带来的流量和线索要能接住——表单加"来源"字段（含 AI 搜索选项）、按被引用的具体页面设计首触话术（对方读的是对比页还是价格页，开场就不同）、把"哪类页面带来 SQL"回传给内容侧。
- **数据回路**：内容侧每月输出"被引用页面 Top 10 + 事实一致性错误清单" → Site 修页与模板 → SDR 记录线索来源与质量 → 反推下一批优先改造的页面。没有这个回路，GEO 就退化成发稿。
- **分工红线**：Site 不对排名与引用做承诺，只承诺"可抓取、可解析、事实准确、结构合规"；引用与提及属于内容与站外运营的 KPI。

### 8.4 可验证的 90 天目标（建议值，按基线调整）

| 阶段 | 目标 | 验收方式 |
|---|---|---|
| 30 天 | 词库 40 条定稿；5 类页各 1 个样板上线；技术审计清零（robots、Schema、响应时间） | 审计清单逐项打勾；Rich Results Test 通过截图 |
| 60 天 | 20 个核心页完成答案优先改造；FAQ Schema 覆盖 ≥10 页；站外 NAP + sameAs ≥3 处一致 | 抽检 10 页首 100 字有答案；sameAs 链接可访问 |
| 90 天 | 40 条 query 中 ≥15 条出现品牌提及或被引用；被引用 URL ≥8 个且分属 ≥3 类模板；事实一致性抽检 20 条正确率 ≥90%；表单"来源=AI 搜索"样本 ≥20 | 复测记录表 + 事实一致性打分表 + 线索来源报表（三者同时成立才算达成） |

## 9. 原文里不可靠或已过时的部分

1. **"78% 的 AI Overviews 含列表"**（§3.3）：单一营销博客的统计，无口径与抽样说明，只能当方向性提示，不要写进对外材料。
2. **"含统计数据与引用可使可见性提升 40%+"**（§3.4）：源自 GEO 早期论文的实验结论，样本与任务设置有限，不能当作承诺值。
3. **"服务器响应 <500ms 的站点更容易进 AI 摘要"**（§4.3）：相关性观察、来源质量弱（引用的是论坛讨论），只能作为性能目标而非因果结论。
4. **"品牌网络提及是与 AI 可见性关联度最高的因素"**（§5.1）：结论随平台与时间波动大，应视为高优先级假设并用自己的数据验证。
5. **Reddit / Quora 作为主要引用源**（§5.2）：这是 2024–2025 年的阶段性观测，平台授权与抓取政策变化会迅速改写格局，需按季度重测。
6. **robots 口径混淆**（§4.3）：把 Google-Extended 与 AI Overviews 抓取并列；实际 Google-Extended 只控制 Gemini 训练/grounding，不影响搜索收录，按此决策会误伤或误放。
7. **HARO 作为常规渠道**（§5.3）：该服务已多次易主/停摆，渠道本身会消失——要记的是"给记者提供专家见解换提及"这个机制，不是平台名。
8. **Bankrate"AI 大规模生成 + 人工审核"案例**（§10.1）：YMYL 场景的个案，与当前对规模化低质内容的治理方向存在张力，不能直接复制到普通站点。
9. **Broworks 的"90 天 10% 流量来自 LLM、SQL 转化 27%"**（§10.1）：服务商自述、无第三方复核，只能作为"值得测"的假设。
10. **工具名单时效**（§7.1）：AI 可见性工具赛道一年内已多次洗牌，本文只保留现有页面在用的工具；名单类信息建议每半年核对一次链接与功能。
11. **"核心页面 >1500 字"**（§6.3 清单）：来自博客的经验值，不是引擎要求；按"问题是否被完整回答"判断，不按字数。
