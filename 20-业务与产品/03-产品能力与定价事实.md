## 二、SDR 功能事实

> 【事实】功能来自 [SDR 帮助中心](https://sdr.trademind.global/help)、[官网](https://sdr.trademind.global/)、[套餐 API](https://sdr.trademind.global/api/v1/public/plans) 的功能清单。**工作台需登录，本文未进入内部界面**，因此"模块存在"是事实，"界面长什么样、数据覆盖多少、效果如何"未验证。

| 模块 | 功能事实 | 边界 / 注意 |
|---|---|---|
| 产品与知识库 | 产品档案、SKU 管理、HS 编码、企业知识库、官网学习、文件上传（文件最大 20MB；支持 TXT / MD / CSV / JSON / DOCX / XLSX / PDF） | 档案质量决定后面所有环节，交付时要配"建档"这一步 |
| 市场研究 | 全球市场筛选、产品市场雷达、产品国家分析、综合市场报告 | 报告依赖数据源覆盖，缺失会标注，不用别国数据替代 |
| 产业地图 | 目标国家、买家角色、渠道方向、证据、策略快照 | 必须人工审核确认后才能用于客户发现 |
| 客户发现 | 公开商业轨 + 海关轨、候选企业审核、AI 背调、联系人 | HS 命中只是一类匹配证据，不等于正在采购你的具体产品 |
| 客户管理 | 客户档案、意向评分、采购信号、客户监控 | 评分用于排序，不承诺成交概率 |
| 销售执行 | 销售打法、AI 建议、开发信草稿、邮件接管、商机推进 | 草稿需人工编辑确认，不自动发信 |
| 商机 / 报价 | 资格审查、需求确认、方案报价、报价版本管理 | "需求确认"不等于"资格审查通过" |
| 单据 | 报价单、PI、销售合同、订单确认、商业发票、装箱单、COO 资料、COA、C of C、产品资料、RFQ 响应（模板中心在线填写 / 下载） | 单据金额与条款需业务与财务确认 |
| 工具 | HS 查询、关税查询、汇率查询、数据字典、外贸模板 | 静态工具与 AI 调用分开计费 |
| 系统 | 套餐、AI 用量、席位、角色权限 | 用量以服务端账本为准；失败不一定不扣额度 |

### 2.1 端到端链路（对外讲解顺序）

```text
① 产品档案 / 知识库 → ② 市场研究 → ③ 产业地图与策略确认（人工审核）→ ④ 买家发现与审核
→ ⑤ 客户档案 / 意向评分 → ⑥ 销售跟进（打法 → 建议 → 开发信 → 邮件接管）→ ⑦ 商机 / 报价 / 单据
```

【判断】这条链路的壁垒不在"AI 写文案"，而在产品档案、HS 编码、市场策略、买家证据、商机报价这套数据结构；讲方案时按这条线讲，比按功能菜单讲更容易被听懂。

**套餐分层的关键分水岭（事实）**

| 从哪一档开始有 | 包含什么 |
|---|---|
| 个人 PLUS | 研究与发现：50 个联系人/期、2 个产品档案、6 个产业地图组合 |

| 企业旗舰版 | 深度情报：竞对洞察、上线检查 |

**计费与交付要点**

1. 【事实】价格档位按"联系人发现数 / AI 额度 / 席位 / 产品档案 / 产业地图组合"分层，企业版再叠加销售执行模块。
2. 【判断】API 配额字段名为 `contact_discovery_per_cycle` / `ai_tokens_per_cycle`，"每期"按所购周期（1 / 3 / 12 个月）重置；具体重置规则待内部确认，报价时不要自行解释。
3. 【事实】公开 API 只提供五档套餐，**没有联系人加购、席位加购的公开价目**。【待确认】加购单价由谁定、能否拆开卖，需内部确认后再报。
4. 【事实】支付方式为支付宝；体验版到期即止，不自动转付费（页面上是"注册后通过支付宝付款，成功开通后开始计时"）。
5. 【判断】年付折扣随档位上升而下降（16.7% → 9.2% → 6.7% → 7.2%），是"高客单折扣更克制"的做法，报价时不要反向给高客单更大折扣，否则破坏价格梯度。

【判断】这张表里最危险的是"标准版比体验版少功能"：客户拿 ¥29.8 的体验版对比 ¥2,000 的标准版，会发现少了市场报告与国家分析。这不一定是产品真缺，更可能是权益清单维护不同步，但在成交现场等同于"越贵越少"。

### 5.1 B2B / B2C 差异（报价与交付时按此分）

| 维度 | B2B 询盘站 | B2C 商城 |
|---|---|---|
| 页面要回答 | 用途、型号、材质、尺寸、规格范围、定制方式、MOQ、交期、报价条件、工厂与认证 | 商品名称、价格与币种、规格、库存、使用说明、配送范围与时效、退换条件 |
| 转化路径 | 每个关键产品页给明确询盘 / 联系入口；询盘围绕型号、数量、目的地、采购要求 | 购物车 → 结算 → 支付 → 通知 → 订单状态 |
| 收款 | 通常不涉及线上收款；报价与合同线下走 | 商家以自身主体申请收款渠道，平台不代收、不混入平台服务订单 |
| 当前自助可得性 | **0 套模板**，需顾问 | 5 套模板，可自助 |
| 验收依据 | 询盘接收与人工对接真实可用 | 购物车、结算、通知、订单状态链路按供应商支持的测试方式核对 |

### 5.2 首页与配置页的口径差异（事实）

| 项 | 首页写的 | 配置页实际 | 处理 |

## 十、报价与交付前检查

**报价前 8 问（SDR）**

1. 客户的出口产品能否归到 HS 编码？有没有现成产品档案与规格表？
2. 目标国家 / 市场有几个？要不要先做市场研究？
3. 团队几个人用？需要几个席位、几个产品档案？
4. 联系人发现需求大概多少条/月？（对照 50 / 500 / 1,000 / 2,000 档位）
5. 要不要邮件接管、报价管理、商机中心？（这三项从企业标准版起）
6. 是否要开发票、签合同、走对公？主体用南京中造软件有限公司。
7. 是否需要私有化 / 数据隔离 / 合规说明？（当前无公开方案，属项目制）
8. 客户是否接受"AI 辅助 + 人工确认"的边界？

**报价前 6 问（Site）**

1. B2B 还是 B2C？（B2B 当前没有自助模板，直接转顾问方案）
2. 需要哪些语言、币种、结算方式？
3. 产品数量与资料完整度（图片是否有授权、规格表是否齐）？
4. 要不要 AI 询盘客服、GEO、多语言等能力项？
5. 域名、服务器 / 托管、支付、物流、邮件由谁买、谁续费？
6. 交付范围与验收标准（页面数、语言数、修改次数）写进合同了吗？

**交付前 6 查**

- 主体名称与备案号（苏ICP备2023031871号-10）是否与合同一致；
- 报价单是否把首次 / 续费 / 增购 / 第三方费用分开列；
- 权益是否逐项对照当前套餐（不要凭记忆承诺）；
- 是否有书面交付范围与验收条件；
- 数据与素材授权是否留痕（模板、图片、字体）；
- 客户是否被告知 AI 输出需人工复核、平台不代收货款。
