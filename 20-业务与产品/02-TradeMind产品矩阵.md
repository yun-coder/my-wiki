## 三、主推一：TradeMind AI SDR

一句话：从市场研究、买家发现到客户跟进、商机报价的外贸客户开发工作台（主标语"找到值得跟进的全球买家"）。

### 3.1 解决什么问题

| 客户的真实问题 | SDR 对应环节 | 证据 |
|---|---|---|
| 产品资料散在 Excel / PPT / 网站，写开发信没有统一事实基础 | 产品档案、SKU、HS 编码、企业知识库、官网学习 | 官网 + 帮助中心 |
| 国家多市场多，不知道先研究哪个 | 全球市场筛选、产品市场雷达、单国分析、综合市场报告 | 官网 + 套餐 API 功能清单 |
| 拿到名单不知道谁值得跟，缺企业角色与贸易证据 | 产业地图（买家角色 / 渠道 / 证据）、候选审核、AI 背调 | 帮助中心 |
| 跟进靠个人记忆，交接难，商机与报价脱节 | 客户档案、意向评分、采购信号、商机中心、报价版本 | 官网 + 套餐 API |
| 开发信、报价、单据重复劳动 | 开发信草稿、邮件接管、报价单 / PI / 发票 / 装箱单等模板中心 | 官网 + 帮助中心 |

### 3.2 能力边界（能做什么 / 不做什么）

| 能 | 不能 / 不承诺 |
|---|---|
| 把七段链路串成一个工作台：产品档案 → 市场研究 → 产业地图 → 买家发现 → 客户档案 → 销售跟进 → 商机报价 / 单据 | 不保证 HS 命中就等于客户正在采购你的具体产品；HS 只是一类匹配证据 |
| 用 AI 做背调、写开发信草稿、给销售建议 | 不自动发信：草稿需人工编辑与确认；邮件接管不等于自动成交 |
| 意向评分用于线索排序 | 评分不是成交概率，不能当承诺写进合同 |
| 数据缺失时标注缺口 | 不用其他国家 / 年份数据替代；缺失就是缺失 |
| 按服务端账本计 AI 用量 | AI 调用失败不一定不扣额度，报价时要说明 |

> 【事实】以上边界由 [SDR 帮助中心](https://sdr.trademind.global/help) 明确写出。【判断】这套"先把边界写清楚"的做法是加分项，尤其对外贸 B2B；但官网首页的"191 国 / 20+ 数据源 / 8.6% 平均转化率"没有口径定义，销售口头引用时极易变成过度承诺。

### 3.3 目标客户画像（ICP）

- 有明确出口产品、能归到 HS 编码；
- 目标市场不止一个，或要系统研究新市场；
- 有 1 人以上外贸团队，或 SOHO 要放大个人产能；
- 愿意按"档案—知识库—策略—发现—跟进"的流程走，而不是只要一份名单。
- 反例（不适合硬推）：只想要名单的、没有产品资料的、期望 AI 全自动发信成交的、预算只有几百元且不愿投入配置时间的。

### 3.4 与同类产品的差异

| 客户原本会选 | 客户为什么选它 | SDR 的差异 |
|---|---|---|
| 海关数据商 / 外贸 CRM | 数据积累深、团队熟悉 | 把海关数据放进"研究—发现—跟进—报价"工作流，不只给名单 |
| 全球销售智能（Apollo、ZoomInfo、Lusha 类） | 海外联系人数据、邮件自动化 | 中国外贸场景、HS 编码、中文界面、报价与单据 |
| 通用 AI + Excel 手工 | 便宜、灵活 | 结构化产品档案、策略、证据、商机与用量管理 |
| 自建数据 + CRM | 可定制、数据自有 | 开箱即用、上线快、AI 能力内置 |

【判断】SDR 最该打的不是"数据量最大"，而是"外贸业务员每天真的能用起来"。壁垒在产品档案—HS—策略—证据—商机这套数据结构，不在 AI 写文案。

### 3.5 成熟度与缺口

| 维度 | 现状 | 影响 |
|---|---|---|
| 功能完整度 | 链路长，从档案到单据都有对应模块 | 优势，但学习成本高，需要行业模板与首单陪跑 |
| 可验证性 | 缺公开客户案例、数据覆盖明细、效果基准 | 售前只能讲功能，讲不出结果 |
| 试用体验 | 体验版联系人发现额度为 0 | 新用户验证不到最核心的买家发现能力 |
| 权益矩阵 | 页面 / API 功能名与包含关系有冲突，出现"升级反而少功能" | 报价与客服解释成本高（详见 [[03-产品能力与定价事实]]） |
| 数据合规 | 海关、企业、联系人数据来源与授权未公开说明 | 中大型客户尽调会卡住 |

【判断】SDR 下一步不该再加功能，而是补证据（3–5 个可公开案例 + 数据覆盖说明）、降试用门槛（给 5–10 个联系人发现或一份样例买家报告）、把权益矩阵做成唯一版本。

## 四、主推二：TradeMind Site

一句话：选模板、选能力项、自动开通并交付商户台的外贸独立站建站服务（主标语"每一个独立站，都值得被认真交付"）。

### 4.1 解决什么问题

| 客户的真实问题 | Site 对应做法 |
|---|---|
| 定制建站贵、周期长、沟通成本高 | 配置页选模板与能力项，服务端即时报价，下单后自动开站 |
| 模板站"好看但不好用"，缺询盘 / 交易链路 | 能力项含多语言、邮件发送、AI 询盘客服、产品套件、基础套件、GEO |
| 多语言、支付、物流、税务配置复杂 | 下单前定语言、币种、结算方式；第三方费用单独列 |
| 上线后没有版本、备份、故障处理 | 商户台含订单、版本、备份、执行日志、手机推送；失败可重试且不重复计费 |
| 不知道域名、服务器、第三方费用归谁 | 费用说明页要求首次报价、续费、增购、第三方费用分开列 |

### 4.2 能力边界

| 平台做 | 平台不做 |
|---|---|
| 开通站点运行时与数据库、按依赖装模板与能力项、交付商户台 | 不代收消费者货款：消费者支付由商家自行配置结算通道 |
| 提供 1 站 1 库隔离、制品准入审核、服务端验签、整站备份 | 不承诺流量、询盘量与转化：上线完成不等于经营效果 |
| 配置页自助下单、支付后异步开通、失败重试 | 不默认全包第三方费用（域名、托管、支付、物流、邮件） |
| B2B 询盘站与 B2C 商城两种业务类型 | B2B 暂无可选套餐时，不能直接套用 B2C 套餐 |

> 【事实】平台约束与责任边界见 [Site 首页](https://site.trademind.global/)、[服务边界](https://site.trademind.global/support)、[费用说明](https://site.trademind.global/services/pricing)、[B2B 方案](https://site.trademind.global/solutions/b2b)。

### 4.3 客群分野：B2B 与 B2C 是两门生意

| 维度 | B2B 询盘站 | B2C 商城 |
|---|---|---|
| 买家的下一步 | 看懂规格、判断是否符合要求、发起询盘 | 加购、结算、收货、退换 |
| 页面重点 | 产品用途 / 型号 / 材质 / 规格范围 / 定制方式、MOQ、交期、资质与认证 | 商品信息、价格币种、库存、配送范围与时效、退换条件 |
| 验收标准 | 询盘接收与人工跟进链路真实可用 | 购物车、结算、通知、订单状态链路真实可用 |
| 当前自助目录 | **0 套模板**，只能转顾问 | 5 套模板可自助 |
| 该谁卖 | 顾问 / FDE 带方案报价 | 可自助，也可顾问 |

### 4.4 与同类产品的差异

| 替代方案 | 客户为什么选 | Site 的差异 |
|---|---|---|
| Shopify / 店匠 | 生态成熟、插件多、B2C 体验好 | 中国外贸场景、B2B 询盘、中文服务、交付型开站 |
| WordPress / WooCommerce | 自由度高、成本可控 | 免开发、自动开通、版本 / 备份、商户台 |
| 外贸建站服务商 | 定制、有人服务 | 标准化配置 + 自动开站 + 流程透明 |
| 阿里国际站 | 有流量与买家资源 | 独立品牌、数据自有、不依赖平台流量 |
| 低价模板站 | 便宜、快 | 交付约束、支付验签、多站点管理、开放接口 |

【判断】Site 的差异不在"模板更多"，而在"交付确定性"：配置、报价、支付、开通、商户台、版本备份是一条链。这个价值必须用案例和 SLA 证明，靠页面文案证不了。

### 4.5 成熟度与缺口

| 维度 | 现状 | 影响 |
|---|---|---|
| B2B 自助链路 | 0 套 B2B 模板，配置页提示"当前暂无已上架页面模板" | 核心客群（外贸 B2B 工厂）走不到自助开通，主推与货架不匹配 |
| 定价 | 一单一议（已确认策略），配置页只上架 7 天免费体验 | 客户在页面拿不到数字，无法与 Shopify / 店匠比价 |
| 首页口径 | 仍写"基础版 / 高级版""15 项功能模块""50 / 200 SKU" | 客户去配置页找不存在的基础版 / 高级版 |
| 加购价 | "AI 经营专家包 ¥0.1""社媒智能体 ¥0.1" | 测试痕迹外露，直接损伤专业感 |
| 模板来源 | 多套标注 BeTheme，1 套自研 | 商用授权、二次开发、客户迁移边界未公开 |
| 交付 SLA | 7×24 支持、上线周期均无量化承诺 | 售前无法回答"多久上线""坏了怎么办" |

【判断】Site 现在的问题不是"缺功能"，而是"货架与主推不一致"：对外主推 B2B，但 B2B 是空的。P0 是上 3–5 套 B2B 询盘模板（五金、家具、照明、宠物、工业配件），同时把首页改成"按方案报价"。

| 产品 | 一句话定位 | 该带出去卖的场合 | 不要这样卖 |
|---|---|---|---|
| 官网 SEO / GEO | 诊断官网在搜索结果与 AI 回答里的可见性，给优化建议 | Site 交付后 30–90 天做复检；客户抱怨"有站没询盘"；客户问 AI 搜索怎么被引用 | 不承诺排名、不承诺被 AI 引用、不当独立套餐报价 |

## 六、项目制能力与报价逻辑

| 能力 | 典型触发条件 | 交付物 | 计价单位 |
|---|---|---|---|
| AI 3D 建模 | 产品需要 3D 展示、空间/展会素材、传统建模太慢 | 3D 模型 / 场景素材 + 使用说明 | 按模型量或项目 |
| 中造 RPA | 跨系统重复录入、订单/单证/后台操作有固定流程 | 自动化流程 + 人工确认节点 + 运维 | 按流程条数与复杂度 |
| 企业知识库 | 资料散、新人上手慢、销售经验留不住 | 知识库 + 检索/问答 + 权限 | 按数据量与集成 |
| AI Agent / 工作流 | 需要角色化智能体嵌入真实业务流程 | Agent + 工作流 + 系统对接 | 按角色数与集成数 |
| 行业定制 | 通用工具不贴合，需要改流程或对接 ERP/CRM | 诊断报告 + 方案 + 开发 + 部署 | 按阶段 / 里程碑 |

**报价逻辑（判断 + 已确认边界）**

1. 【事实】公开渠道没有项目制价目表：官网只给"诊断 → 匹配 → 落地"三步与"规划—设计—研发—部署—优化"的服务描述，没有起价、周期、验收标准。
2. 【判断】项目制应按"诊断（是否值得做）→ 方案与工作量（多少钱）→ 开发（里程碑付款）→ 部署与培训 → 运维"分段报价，每段有交付物，避免一次性总包。
3. 【判断】报价前必须问清五件事：现有系统与数据在哪、要不要私有化、对接哪些系统、谁验收、上线后谁运维。这五项决定工作量，也决定会不会做亏。
4. 【判断】组合报价思路（档案建议，非公开价、未经内部确认）：SDR + Site 年付打包，送建站配置或首月陪跑；Site 客户加购 SDR 给首月联系人包折扣；SDR 客户加购 Site 免首年模板费或送 SEO/GEO 检测；内容与信用证作为增值包按用量/项目计。
5. 【待确认】项目制起价、标准交付周期、验收标准、私有化部署选项，目前都没有内部统一版本，销售只能口头估。

## 七、组合故事：一条主线，不是六个并列

```text
内容 / SEO / GEO ──→ 让客户找到你（流量与 AI 可见性）
        ↓
TradeMind SDR ─────→ 找到谁值得跟（研究 → 发现 → 证据 → 开发信 → 商机）
        ↓
TradeMind Site ────→ 客户来了看什么（建站 → 询盘/订单 → 承接）
        ↓
报价 / 单据 / 信用证 → 成交后怎么履约（PI、发票、装箱单、审证）
```

【判断】对外只讲这一条主线：SDR 负责"找到人"，Site 负责"接住人"，内容与 SEO/GEO 负责"让人找到"，信用证与单据负责"履约"。四款协同在这条线上各有位置，所以不需要并列主推，也不该各讲一套故事。
