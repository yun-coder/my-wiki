# AI资讯统一采集与知识库渐进整理设计

## 目标

将 Chrome `AI资讯` 文件夹的 20 个动态书签接入现有每日采集流程，统一完成规范化、去重、分类和质量过滤；修复 Windows 定时任务的失效路径，并为知识库后续分批清理建立稳定入口。

## 设计

- `scripts/daily_collector.py` 是唯一的每日采集入口。
- 每次运行从当前 Chrome Default 配置的 `Bookmarks` JSON 读取名为 `AI资讯` 的文件夹，因此用户在 Chrome 中调整书签后无需再次导出。
- 书签 URL 移除常见跟踪参数后按规范化 URL 去重；保留有意义的业务参数。
- 书签按域名和标题分为 `社交入口`、`资讯聚合`、`技术源`、`社区/工作入口` 四类。
- 社交和登录型社区作为观察源纳入清单，但不把登录页或首页导航写入长期洞察库；公开资讯聚合和技术源参与文章采集。
- Chrome 文件不可读时使用仓库内 `bookmarks_2026_7_23.html` 仅作兼容提示，不伪造 JSON 采集结果，并在日志中明确告警。
- `digest_ai_news.py` 保留可执行兼容入口，转调主采集器，避免两套流程各自写结果。
- `MyWikiDailyTask.xml` 调用仓库内 `run_daily_collector.bat`，日志继续写入 `state/daily/logs`。

## 知识库质量边界

- 新条目继续经过现有 URL、标题和摘要检查。
- 导航标题、登录提示和仅有“待补充正文分析”的摘要不得成为主库精选条目。
- 现有历史条目不做一次性删除；后续按主题每批 20-30 条审阅，低质量条目移动至 `AI知识库/99-归档` 并保留来源。

## 验证

- 单元测试覆盖书签 JSON 读取、路径筛选、分类、跟踪参数去重和观察源行为。
- 运行全量 `python -m unittest discover -s tests -v`。
- 运行采集器 `--quick`，确认当前 Chrome 书签被读取、任务入口可执行且失败时返回非零状态。
