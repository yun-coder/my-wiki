## 一、执行摘要

### 1.1 公司是谁

【事实】南京中造软件有限公司成立于 2020-12-25，定位 **企业级 AI 智能化建设服务商**，围绕 **AI Agent、企业知识库、AI 工作流** 三项能力，提供从 AI 应用规划、系统设计、产品研发、部署落地到持续优化的服务。外贸是其重点垂直行业，TradeMind / 智贸是外贸方向的品牌与产品体系。

【判断】中造软件不是单一 SaaS 公司，而是 **“产品化 SaaS + AI 项目交付”双轮模式**：
- 产品化：TradeMind AI SDR、TradeMind Site 等订阅/开通型产品；
- 项目制：企业 AI Agent、知识库、工作流、RPA、3D、行业定制等解决方案。

### 1.2 两张产品牌

```text
中造软件（公司/技术品牌）
└─ TradeMind / 智贸（外贸行业 AI 品牌）
   ├─ TradeMind AI SDR      当前主推｜获客与销售执行
   ├─ TradeMind Site        当前主推｜独立站建站与承接
   ├─ 官网 SEO / GEO        协同｜look.trademind.global
   ├─ 外贸内容运营          协同｜zzpms.com
   ├─ 外贸爆款分析与生图    协同｜zzpms.com
   └─ 信用证审核            协同/内测｜zzpms.com
```

### 1.3 两款主推产品的一句话画像

| 产品 | 一句话画像 | 当前最强卖点 | 当前最大短板 |
|---|---|---|---|
| **TradeMind AI SDR** | 从市场研究、买家发现到客户跟进、商机报价的外贸客户开发工作台 | 中国外贸场景的端到端闭环：HS/海关数据 + AI 研究 + 开发信 + 报价/单据 | 数据质量与效果缺少公开证据；体验版联系人额度为 0，难以验证核心价值 |
| **TradeMind Site** | 选模板、选能力项、自动开通并交付商户台的独立站建站服务 | 交付型建站：自动开站、商户台、版本/备份、B2B/B2C 双模式 | B2B 配置页 0 套模板；价格按单一议、页面无法比价；¥0.1 加购价像测试数据 |

### 1.4 五条关键判断

1. **主推组合是对的，但对外叙事需要收拢。** SDR 负责“找到人”，Site 负责“接住人”，两者天然构成“获客—建站—询盘—跟进”的闭环；其余 4 款更适合作为附售能力，而不是并列主推。
2. **SDR 的产品完整度高，但“可验证性”不足。** 功能覆盖从产品档案到报价单据，链路很长；公开材料缺少客户案例、数据覆盖明细、效果基准。体验版 0 联系人额度，会使新用户无法验证最核心的买家发现能力。
3. **Site 的交付理念清晰，但 B2B 自助链路是断的。** B2C 有 5 套模板可自助配置；B2B 配置页显示 0 套模板，而 B2B 外贸工厂恰恰是 TradeMind 的核心客群。
4. **品牌与命名存在碎片化。** “AI SDR / 外贸 SDR”“独立站 / 外贸独立站”“内容运营 / AI 运营工作台”“爆款分析与生图 / 爆款洞察工坊”“信用证审核 / 信用证 AI 审核与自动制单”多套叫法并存，影响搜索、销售话术与产品矩阵理解。
5. **价格体系“一明一暗”。** SDR 价格公开、档位清晰；Site 只有免费体验，付费价格不透明，且加购价出现 ¥0.1 的测试痕迹。两条产品线的定价成熟度不一致。

### 1.5 建议优先做的五件事

| 优先级 | 动作 | 目的 |
|---|---|---|
| P0 | 统一公司名、产品名、产品数量口径 | 避免合同/品牌/销售材料互相打架 |
| P0 | 上架 Site B2B 模板，并把“按方案报价”写进配置页 | 让核心客群能自助走到报价与开通，而不是卡在 0 模板 |
| P0 | 调整 SDR 体验版权益（至少给 5–10 个联系人发现或一份样例买家报告） | 让新用户验证核心价值，而不是只体验前端 |
| P1 | 做 3–5 个可公开的客户案例（行业、国家、前后对比、用时、用量） | 补足 SDR/Site 最缺的信任证据 |
| P1 | 建立“2 主推 + 4 协同 + N 项目”的产品分层与组合报价 | 收敛销售注意力，提升客单与交叉销售 |

## 三、AI 解决方案画像

### 3.1 定义与边界

【事实】中造软件的 AI 解决方案覆盖 **获客增长、内容运营、电商提效、知识沉淀、自动化执行、行业定制**，以 AI Agent、企业知识库、AI 工作流为技术底座。

【判断】“AI 解决方案”不是单一 SKU，而是三层生意的统称：
1. **产品化方案**：SDR、Site、内容工具、信用证审核等，有明确入口和价格；
2. **组合方案**：外贸增长（SDR + Site + 内容 + 单证）、内容运营（工作台 + 爆款 + 3D）；
3. **项目制方案**：企业知识库、Agent、工作流、RPA、行业定制，按诊断—设计—开发—部署收费。

### 3.2 能力栈

| 层 | 能力 | 客户感知 |
|---|---|---|
| 交互层 | AI Agent / AI 助手 | “能对话、能执行任务、能辅助员工” |
| 知识层 | 企业知识库 / 官网学习 | “AI 懂我的产品和业务” |
| 流程层 | AI 工作流 / RPA | “重复流程自动跑，关键节点人工确认” |
| 数据层 | 贸易数据 / 市场情报 | “知道市场在哪、客户是谁” |
| 交付层 | 规划、设计、研发、部署、优化 | “不是买工具，是建能力” |

### 3.3 方案组合

| 方案 | 解决的问题 | 对应产品/能力 |
|---|---|---|
| **外贸增长 / 智贸** | 海外客户开发效率低、推广成本高、询盘跟进依赖人工、客户信息难沉淀 | AI SDR + Site + 内容运营 + 信用证审核 |
| **内容运营** | 文案、图片、爆款拆解、3D 素材生产成本高 | AI 运营工作台、爆款洞察工坊、AI 3D 建模 |
| **电商提效** | 商品图、卖点、详情页、素材复用 | 爆款分析与生图、AI 运营工作台 |
| **知识沉淀** | 企业知识散、新人上手慢、销售经验留不住 | 企业知识库、官网学习、销售打法 |
| **自动化执行** | 重复录入、跨系统操作、流程断点 | 中造 RPA、AI 工作流 |
| **行业定制** | 通用工具不贴合业务 | Agent/知识库/工作流项目制 |

### 3.4 目标客户

- **制造业源头工厂**：有产品优势，想建立自主海外获客能力。
- **外贸企业/贸易公司**：产品线多、业务环节多，需要提高开发与跟进效率。
- **外贸个人/SOHO**：一个人兼顾查客户、做内容、跟业务，需要把重复工作交给 AI。
- **内容/电商团队**：需要批量生产文案、图片、爆款素材。
- **中大型企业**：需要私有知识库、Agent、工作流、RPA 的项目制建设。

### 3.5 交付模式

【事实】官网描述为“AI 应用规划 → 系统设计 → 产品研发 → 部署落地 → 持续优化”的一站式服务；解决方案页给出“诊断 → 匹配 → 落地”三步。

【判断】实际销售应区分三种交付：
- **自助开通**：SDR 个人版/企业版、Site 标准配置；
- **顾问开通**：SDR 企业版、Site 定制/B2B；
- **项目交付**：知识库、Agent、工作流、RPA、3D、行业定制。

### 3.6 差异化

1. **外贸垂直深**：不是通用 AI 工具，而是围绕外贸获客、建站、内容、单证做深。
2. **端到端**：从市场研究到报价单据，链路比单点工具长。
3. **人工可控**：帮助中心反复强调“AI 输出要核对、发送前人工确认、评分不是成交承诺”，符合 B2B 外贸的风险偏好。
4. **产品 + 项目双轮**：标准化产品负责规模化，项目制负责客单与深度。

### 3.7 证据缺口

- 缺少公开的客户案例、行业覆盖、效果数据；
- “AI 解决方案”的报价体系、交付周期、验收标准未公开；
- 项目制与产品制的边界、团队产能、合作伙伴体系不清晰；
- 需要补充数据合规、模型选型、私有化部署、安全资质说明。

### 4.2 定位、ICP 与痛点

**定位**：不是“卖海关数据”，也不是“卖 AI 写开发信”，而是把 **市场研究—买家发现—客户审核—销售跟进—商机报价—单据** 串成一个工作台。

**ICP**：
- 有明确出口产品、可归类 HS 编码；
- 目标市场不止一个国家，或需要系统研究新市场；
- 有 1 人以上外贸业务团队，或 SOHO 需要放大个人产能；
- 愿意按“产品档案—知识库—策略—发现—跟进”的流程操作，而不是只要一份名单。

**痛点**：
- 产品资料散落在 Excel/PPT/网站，市场研究和开发信缺少统一事实基础；
- 国家多、市场多，不知道先研究哪个；
- 拿到名单后不知道谁值得跟，缺少企业角色与贸易证据；
- 客户跟进靠个人记忆，交接难，商机与报价脱节；
- 开发信、报价、单据重复劳动多。


【判断】这条链路的真正壁垒不在“AI 写文案”，而在 **产品档案、HS 编码、市场策略、买家证据、商机/报价** 的数据结构。谁能把这条链路做顺，谁就更难被替代。

### 4.5 数据、AI 与人工边界

【事实】帮助中心明确写了多条边界：
- 海关 HS 命中只是一类匹配证据，不能单独证明客户正在采购你的具体产品；
- 意向评分用于排序，不是成交概率保证；
- AI 生成的开发信、报价、单据需要人工核对；
- 数据缺失要标注，不能用其他国家/年份数据替代；
- AI 调用按服务端账本计费，失败不一定不扣额度。

【判断】这种“把边界写清楚”的做法是加分项，尤其对外贸 B2B 客户。但官网首页的“191 个国家/地区、20+ 数据来源、8.6% 平均转化率”属于营销口径，缺少定义与证据，建议在销售材料中补充口径说明，避免过度承诺。

| 阿里国际站 | 流量入口、买家资源 | 独立品牌、数据自有、不依赖平台流量 |
| 模板站/低价建站 | 便宜、快 | 交付约束、支付验签、多站点管理、开放接口 |

【判断】Site 的差异化不在“模板更多”，而在 **“交付确定性”**：配置、报价、支付、开通、商户台、版本/备份是一条链。这个价值需要案例和 SLA 来证明。

### 5.8 风险与短板

| 风险 | 说明 | 建议 |
|---|---|---|
| B2B 模板为 0 | 核心客群无法自助 | 优先上架 3–5 套 B2B 询盘站模板（五金、家具、照明、宠物、工业配件） |
| 价格不可自助比较 | 一单一议是策略，但配置页给不出数字，标准化买家会流失 | 页面明示“按方案报价”，并提供起步区间/典型方案价，减少询价往返 |
| ¥0.1 加购价 | 像测试数据，损害信任 | 立即隐藏或改为真实价格 |
| 模板来源/授权 | 多套模板标注 BeTheme | 明确授权范围、可商用性、二次开发边界 |
| 交付周期不确定 | 依赖资料、语言、产品数量 | 给出标准交付 SLA/资料清单/验收标准 |
| 无公开案例/SLA | 7×24 支持、稳定性无证据 | 发布案例、uptime、支持响应说明 |
| 竞争激烈 | Shopify/店匠/WordPress/服务商 | 用“B2B 询盘 + 交付确定性 + 中国服务”聚焦 |

### 5.9 关键指标

- 配置→支付转化率；
- 模板选择率、B2B/B2C 占比；
- 从支付到站点可用的用时；
- 加购 attach rate（AI 客服、GEO、社媒智能体）；
- 上线后 30/90 天询盘量/订单量（需客户授权）；
- 支持工单量、开通失败率、重试成功率；
- 续费/升级、站点数扩张、转介绍。

- **Site**：交付理念是优势，一单一议也是既定策略；下一步的关键是 **补 B2B 模板、把“按方案报价”写进页面、去掉测试价**。
- **公司层**：从“多产品并行”转向“2 主推 + 4 协同 + N 项目”，用组合故事提升客单与品牌清晰度。

### 11.3 白板补出来的三条洞察

1. **价值链五项就是公司自己定义的交付清单**：报价体系、使用手册、客户服务、定制、对接。用它去核对两款主推——SDR 的短板（缺案例、权益矩阵乱）落在“报价体系/使用手册”，Site 的短板（B2B 模板 0、一单一议没法比价）落在“报价体系/定制/对接”。这比笼统说“体验不好”更能定位问题。
2. **白板明确写“私域（利润）”**：利润不在平台流量里。这解释了 SDR 为什么强调数据自有、Site 为什么强调“独立站不依赖平台流量”——两条产品线的底层假设是一致的。
3. **“完整交付”被放在价值链顶端**：说明公司对产品的定义是“交付物”而非“软件功能”。因此 Site 的评分里“交付可规模化”比“模板数量”更该被考核。

### 11.4 白板带来的新待确认
