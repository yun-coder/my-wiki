# 节拍与认领

## 为什么要有节拍

剧本的一句话在生成端是模糊的。"她走进来，坐下，点烟" 是三个动作、三个落点，模型会挑一个演完，另外两个变成背景里的挥手。节拍就是把这句话切成**不可再分的动作或台词**，每拍有一个可以被看见的终点。

节拍也是账本：镜头认领哪几拍，就说明它必须演完哪几件事。剧本改了，重跑一次 `check`，失效的镜头会被点名，而不是到生成时才发现漏了一段。

## 拆节拍的规则

- **一拍一件事。** 动作拍只写一个可见动作，含起点和终点："她把碗码进柜子，关上柜门"。不含"然后""接着"。
- **台词单独成拍。** 一条台词一拍，`speaker` 必填，文本逐字保留（后面要逐字对账）。语气、眼神写在动作拍里，不塞进引号。
- **只写镜头拍得出来的动作。** 挑担上船、搭手卸担这种模型见过千万次的优先；伸篙一挡、睫毛颤这类精巧动作，生成必崩，拆成更常见的动作或改由台词承担。
- **每场至少一个动作拍。** 纯对白场是广播剧。
- **给时长。** 台词按 `charsPerSecond`（默认 4.5 字/秒，含标点）折算，再加 0.3 秒起势；动作按拍估 1.5–3 秒。时长是**下给模型的生成时长**，不是估算值，所以宁可给够。

## 认领的规则

镜头的 `claims` 是一段**连续**的节拍 id：

```json
{ "id": "E01-01-02", "scene": "S01", "segment": "E01-01", "durationSec": 4, "claims": ["B03", "B04"] }
```

脚本会检查：

1. 每个节拍恰好被认领一次（漏了、重了都拦）；
2. 认领的节拍连续且顺序不回退（不许跳拍、不许倒着走）；
3. 一镜不跨场：认领的节拍同属一个 `scene`，且与镜头的 `scene` 一致；
4. 每镜至少一个动作拍（纯台词镜头没有画面可拍）；
5. 认领节拍时长合计与镜头时长相差不超过 `beatBudgetEpsilon`。

## 什么时候拆镜

拆镜的成本几乎为零——多一个镜头不花钱，漏一个动作要重生成。所以拿不准就拆：

- 一个镜头里出现第二个动作 → 拆；
- 人物要横穿空间 → 给走位一个镜头（切掉走路就是瞬移）；
- 同框超过 `maxPeoplePerFrame` → 拆，或让人物退出画面；
- 一次生成超过 `maxSegmentSeconds` → 拆段，段内再切镜；
- 台词装不进 → 先砍动作拍、再压台词，不要靠加快语速硬塞。

## 与生成批次的关系

`segment` 是一次生成。同一段的镜头在模型眼里是一个连续镜头，跨段则各自从头生成——所以：

- 段内切镜可以靠"切/反打"的措辞；
- 段与段之间，必须靠上一段**实际生成的最后一帧**接，不能靠计划；
- 时间结构按**镜头顺序**写，不要把秒数写进提示词（很多模型按顺序而不是按时间戳理解多镜）。
