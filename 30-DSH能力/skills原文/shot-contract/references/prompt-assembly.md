# 由表成文

表是真相，散文是它的投影。散文里不出现表里没有的东西，表里的每个格子也都要落进散文。

## 一个镜头的句序

1. **切/机位**：先说要怎么拍——"反打""切特写""机位在她身后"。它决定了读者站在哪。
2. **动作与表情**：这一镜唯一的那件事，加一个身体锚点。
3. **位置变化**：谁移动了，移到哪，朝哪。没写就等于没动。
4. **这一镜的声音**：环境声、道具声、说话人之外的声音。
5. **台词**：谁说的、用什么声音、眼睛看哪。
6. **锁行**：逐字复述光、身份、位置、朝向、机位侧——用脚本生成，不要手写。

## 锁行

脚本按结构化字段生成：

```
光：<light>。<who>在<pos>，<facing>；…。机位在<side>，<size>。
```

```bash
node scripts/check.mjs locks <file.json>
```

为什么要每镜都重述：模型在切镜之间**什么都不记得**。不重复的光会漂移，不重复的位置会让人物回到上一镜的门口，不重复的机位侧会让人对着空气演戏。锁行不是啰嗦，是每镜的入场证。

改 JSON 改了光、位置或机位，就必须重新生成锁行并替换，否则 `G09` 会拦——这正是它的用途：防止字段和散文各说一套。

## 台词

- **逐字**：JSON 里的台词原样出现在 prompt 里（`G10` 逐字对账）。改词就改 JSON，再重贴。
- **一条台词一个说话人**：同镜两人各说各的，就拆镜；两个人抢一句话，模型会把声音糊在一起。
- **给声音和眼睛**："声音很低，每个字都清楚，眼睛一直看着他"。只写形容词会得到一张死脸。
- **反应是反打**：要拍一个人被台词击中，机位站到台词来的那一侧，让他朝镜头方向看。

## 禁止项

- 不写秒数和时间戳：多镜结构按**镜头顺序**表达，很多模型把秒数当噪声。
- 不写厂牌、片名、明星、真实品牌：分类器认词不认意图。
- 不写空话形容词：电影感、高级感、大片感、杰作、4k/8k —— 换成一个情绪词加一个身体锚点。
- 不写成语和肌肉清单："脸沉下来"会得到一张发灰的脸，"皱眉、咬牙、鼻孔张开"会得到一个在生闷气的人。
- 不把非自愿的结果写成终点：外套被门夹住、滑倒、泼洒——模型会把它演成角色的主动动作。写主观动作，或者把后果留在画外。

## 套模型语法

这个 skill 产出的是**与模型无关的结构 + 散文**。真要下单时，最后套一层该模型的语法（参考图标记、参数键、首尾帧声明），并守两条：

1. 套壳只能**加**，不能改：表、锁行、台词原文一个字都不动。
2. 时长上限、参考图数量这类硬限制，改 `params` 或套壳处，不要改规则。

这样换模型时，丢掉的是壳，留下的是结构与验收。
