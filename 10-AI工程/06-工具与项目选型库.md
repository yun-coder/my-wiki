# 工具与项目选型库

> 这页解决一个问题：**某个能力缺件时，先看哪几个项目，为什么选它。**
> 收录标准：用过、或认真评估过、或社区验证充分。GitHub Star 不作为入选理由。每条只给「定位 + 什么时候选」，细节回到对应方法论页。

## 一、模型与推理

| 项目 | 定位 | 什么时候选 |
|---|---|---|
| [vLLM](https://github.com/vllm-project/vllm) | 高吞吐推理服务 | 有 GPU、要控单位成本、并发稳定 |
| [SGLang](https://github.com/sgl-project/sglang) | 结构化生成与推理优化 | 大量 JSON/工具调用，要压延迟 |
| [Ollama](https://github.com/ollama/ollama) | 本地模型管理 + API | 本地开发、隐私场景、快速试模型 |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) | 本地运行时 | CPU/边缘设备、离线部署 |
| [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory) | 统一微调 | 要做 LoRA/SFT/DPO 且不想自己拼脚本 |
| [Unsloth](https://github.com/unslothai/unsloth) | 高效微调 | 单卡/个人 GPU 微调，省显存省时间 |

## 十二、评估规则

新增项目或决定采用前，至少过一遍：

- 最近 6 个月有提交吗？Issue 有人回吗？有版本发布吗？
- 许可证允许商用吗？有专利/附加条款吗？
- 能本地部署吗？数据出不出域？能换模型吗？
- 有测试、文档、可复现的部署方式吗？
- 显存/内存要求、延迟、并发上限是多少？
- 出了问题时，社区能不能搜到答案？

**判断**：一个项目"能跑起来"和"能维护三年"是两件事。选型时把维护成本算进去，比选功能最多的那个更划算。
