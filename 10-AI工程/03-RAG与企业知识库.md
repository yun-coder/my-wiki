# RAG 与企业知识库

> 这页解决一个问题：**什么样的知识库是真能用，什么样只是"能问答的 Demo"。**

## 一、先分清三个概念

| 概念 | 解决什么 | 典型实现 | 失败表现 |
|---|---|---|---|
| RAG | 从外部资料里检索上下文 | 向量库 + 检索 + 生成 | 答得流畅但引用了不存在的段落 |
| 记忆 | 跨会话保留事实、偏好、经验 | 结构化事实库 + 检索 | 记住过时信息、新旧事实冲突 |
| 知识库 | 组织、权限、版本、生命周期 | 文档系统 + 索引 + 治理 | 内容过期、权限越界、没人维护 |

三者经常被混成一个"企业大脑"，结果每件事都做了一半。**RAG 是技术手段，知识库是产品形态，记忆是长期状态。**

## 二、七段式流水线与失败模式

```text
采集 → 解析 → 切分 → 索引 → 召回 → 重排 → 生成（含引用）
```

| 环节 | 关键动作 | 常见失败 | 对策 |
|---|---|---|---|
| 采集 | 支持 PDF/Word/PPT/网页/扫描件 | 只收文本，丢掉表格图片 | 用 Docling / MinerU / MarkItDown / PaddleOCR 保留结构 |
| 解析 | 保留标题层级、表格、页码、来源 | 标题丢失导致切分错乱 | 解析结果带结构树，不直接拍平成纯文本 |
| 切分 | 按语义/章节切，带父子关系 | 一刀切 512 字，句子断开 | 父子块：小块检索、大块喂给模型 |
| 索引 | 向量 + 关键词 + 元数据 | 只有向量，专有名词搜不到 | 混合索引；元数据（部门、日期、密级）可过滤 |
| 召回 | top-k + 阈值 + 权限过滤 | 召回一堆相似但无用内容 | 先过滤再检索；设相关度阈值，宁缺毋滥 |
| 重排 | 用 cross-encoder 或模型重排 | 直接拿向量分数当相关度 | 加一层重排，收益通常大于换 embedding |
| 生成 | 强制引用、拒答机制 | 编造引用、答非所问 | 提示词要求逐句引用；无依据时明确说"资料中没有" |

## 三、结构保留比 embedding 选型更重要

企业文档的价值大量藏在结构里：条款编号、表格列名、章节层级、图表标题。拍平之后，模型看到的是一堆断句。

- 解析时保留 `标题路径`（如：合同 > 第 3 条 > 付款方式），作为块的元数据。
- 表格单独成块，带表头重复；不要把表格塞进段落。
- 扫描件走 OCR 后必须人工抽检，错字会直接变成错误答案。
- 每个块带来源（文件名、页码），引用时能定位。

## 四、检索：混合 + 重排 + 过滤

单一向量检索在专有名词、型号、人名、条款号上很弱；单一关键词检索在同义改写上很弱。

推荐组合：

1. **粗召回**：向量 top-20 + 关键词（BM25/全文）top-20。
2. **合并去重**：按文档块 id 合并，保留两路分数。
3. **权限与时效过滤**：先排除无权访问和已过期的块。
4. **重排**：取前 8–10 条喂给模型。
5. **阈值**：最高分低于阈值时直接拒答，比硬答更专业。

## 五、引用与可验证

企业用户不信任"一段没有出处的答案"。最低要求：

- 答案中每个事实性句子都能指到具体文档块。
- 前端可点开原文定位到段落/页码。
- 提供"这段不对"的反馈入口，反馈进入修正队列。
- 允许人工标注"标准答案"，作为回归样本。

没有引用能力的知识库，只能用于内部探索，不能对外交付。

## 六、更新与生命周期

知识库的成本 80% 在维护，不在建设。

| 问题 | 机制 |
|---|---|
| 内容过期 | 每个文档带有效期/复核日期；到期自动降权并提醒 |
| 事实冲突 | 同一主题保留版本，回答时优先最新且标注版本 |
| 删除 | 逻辑删除 + 索引同步；被删除内容不得再出现在答案里 |
| 权限 | 文档级/部门级 ACL，检索前过滤，不能只在展示层藏 |
| 变更审计 | 谁在什么时候改了哪份资料，可追溯 |

## 七、评测：最小可用的三张表

1. **召回表**：50 个真实问题 → 期望命中的文档块 → 实际 Top-10 命中率 / MRR。
2. **引用表**：答案中的引用是否真实存在、是否支持该结论（人工抽检 30 条）。
3. **答案表**：正确 / 部分正确 / 错误 / 拒答四分类，统计错误类型（漏答、答错、编造）。

工具：[Ragas](https://github.com/explodinggradients/ragas) 做 RAG 指标、[DeepEval](https://github.com/confident-ai/deepeval) 做用例回归、[Langfuse](https://github.com/langfuse/langfuse) 做线上追踪与成本统计。

## 八、选型（截至 2026-11）

| 需求 | 首选 | 备选 | 判断 |
|---|---|---|---|
| 快速搭企业问答 | RAGFlow | Dify、FastGPT、MaxKB | RAGFlow 解析强；Dify 工作流强；MaxKB 部署简单 |
| 中文文档 + 私有化 | RAGFlow、WeKnora | AnythingLLM | 看是否要国产化与知识图谱 |
| 自己写代码控制每一步 | LlamaIndex | LangChain | LlamaIndex 数据层更顺；要图编排加 LangGraph |
| 向量库 | Qdrant、pgvector | Milvus、Weaviate、Chroma | 已有 Postgres 先用 pgvector；规模大用 Milvus |
| 文档解析 | Docling、MinerU | Unstructured、MarkItDown | 扫描件重 OCR 选 MinerU；结构化保留选 Docling |
| 记忆层 | Mem0、Zep、Hindsight | 自建事实表 | 要"会积累经验"看 Hindsight；要通用记忆看 Mem0 |

**判断**：平台类工具赢在开箱即用，输在调优空间；自研赢在可控，输在解析与评测的工作量。第一版用平台验证需求，第二版再决定是否自研。

## 九、成本与运维

- 索引成本一次性，重排与生成是持续成本；重排用小的 cross-encoder 比再调一次大模型便宜。
- 文档更新要增量索引，不要全量重建。
- 给每个租户/部门设配额，避免一个大文档把索引撑爆。
- 监控三件事：召回命中率、拒答率、平均引用数；任一异常都说明数据或索引出了问题。

## 十、落地检查清单

- [ ] 解析保留了标题、表格、页码、来源
- [ ] 检索是混合的，且有权限过滤与阈值拒答
- [ ] 答案能引用到原文，前端可定位
- [ ] 文档有有效期与复核机制
- [ ] 有 50 条真实问题的回归集
- [ ] 删除与权限变更能同步到索引
- [ ] 线上有追踪（问题、召回、答案、反馈）
