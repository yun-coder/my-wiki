# 评测、成本与安全治理

> 这页解决一个问题：**怎么在上线前证明"它可靠、它不贵、它不会出事"。**

## 一、四类检查，缺一不可

| 类别 | 问什么 | 最低证据 |
|---|---|---|
| 质量 | 做对的概率是多少？错在哪类？ | 固定样本 + 错误分类 |
| 成本 | 一次任务多少钱？随量怎么变？ | 真实调用对账，不是估算 |
| 安全 | 被诱导会不会越权、泄密、乱执行？ | 攻击用例集 + 权限验证 |
| 可靠性 | 超时、限流、依赖挂掉时还能用吗？ | 故障演练记录 |

## 二、评测集怎么建

不要一开始就追求"大而全"，20–50 条真实样本就够发现主要问题。

1. 从真实业务里抽，不用自己编的漂亮问题。
2. 每条写清：输入、期望结果、判定方式（精确匹配 / 规则 / 人工）。
3. 覆盖四类：常规、边界、恶意/诱导、资料缺失。
4. 每次改动（换模型、改提示、改检索）都跑同一套，记录版本。
5. 错误分类固定几个桶：漏答、答错、编造、格式错、超时。桶稳定了才能看趋势。

指标随任务而定，常用：准确率、引用准确率、拒答率、P95 延迟、单任务成本、人工修改率。

## 三、成本核算

成本要按"任务"而不是"接口"算：

```text
单任务成本 = 输入 token × 单价 + 输出 token × 单价 + 重试成本 + 检索/重排成本
```

- 用真实流量对账一次，别信按次估算。
- 缓存命中率是最容易被忽略的杠杆：系统提示、文档、示例的重复前缀都能缓存。
- 给每个任务设硬上限（token、重试、时长），超限失败并告警。
- 成本看板上按"客户/功能/模型"三个维度切，才能定位是谁在烧钱。

## 四、安全：Agent 时代的默认风险

| 风险 | 场景 | 控制 |
|---|---|---|
| 提示注入 | 网页/邮件/文档里藏指令 | 外部内容标记为数据；关键指令只从系统提示来 |
| 越权 | Agent 能读全库、能删数据 | 工具级最小权限；按用户身份过滤，不做超级账号 |
| 数据外泄 | 敏感字段进了第三方模型 | 出域前脱敏；敏感任务走本地模型 |
| 误执行 | 自动发信、下单、改配置 | 不可逆操作强制人工确认；先影子模式 |
| 供应链 | 插件/MCP 服务器不可信 | 只装可信来源；审查其工具权限；可随时卸载 |

**判断**：安全不是加一个"审核模型"就完了，而是权限、数据流、可回滚三件事的组合。

## 五、可靠性

- **超时**：每个外部调用都有超时，不能让一个卡住的请求拖死整个任务。
- **重试**：只对可重试错误退避重试，且操作必须幂等。
- **降级**：主模型不可用 → 备用模型 → 规则兜底；降级后要告知用户。
- **回滚**：配置、提示、模型版本都要能一键回退。
- **观测**：记录每次调用的输入摘要、输出、耗时、成本、错误码；出问题能复盘。

## 六、上线门禁

- [ ] 有固定评测集，最近一次通过率达标
- [ ] 单任务成本已对账，有预算上限
- [ ] 权限模型明确，越权用例测试过
- [ ] 提示注入用例测试过，外部内容不当指令
- [ ] 不可逆操作有确认环节
- [ ] 有超时、重试、降级、回滚
- [ ] 有日志与追踪，能定位单次失败
- [ ] 有人工接管入口
