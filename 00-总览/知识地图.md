# 知识地图

> 这页解决一个问题：面对一堆 AI 与外贸知识，**先看哪、按什么顺序看、它们之间怎么连**。

## 一、两条主线

任何 AI 落地都同时跑在两条链上，缺一条就只是 Demo。

**能力链（把模型变成能交付的系统）**

```text
模型与数据 → 推理部署 → Agent 编排 → 工具 / MCP → RAG 与记忆
         → 业务工作流 → 评测 / 观测 / 安全 → 持续运营
```

**业务链（外贸 B2B 的钱从哪来）**

```text
市场研究 → 内容与获客 → 线索进入 CRM → 报价与跟进
        → 订单与单证 → 交付 → 客户维护与复购
```

两条链的交点就是产品：能力链的每一层落到业务链的某一个环节，才叫「AI 解决方案」；落不下去的，是技术演示。

## 三、三条阅读路径

**路径 A：判断先行（10 分钟）**
`核心判断` → 挑一条你今天要做的 → 进入对应工程页的「落地」小节。

**路径 B：交付一个客户（半天）**
`01-外贸数字化基线`（找环节）→ `02-TradeMind产品矩阵`（看我们有什么）→ `04-AI解决方案交付方法`（怎么设计交付）→ `03-产品能力与定价事实`（报价不翻车）。

**路径 C：自己造一个 AI 系统（按链走）**
`01-模型` → `02-Agent` → `03-RAG` → `05-评测治理`；需要出素材时进 `04-多模态`；缺具体组件时查 `06-选型库`。

## 四、维护边界

- `10-AI工程` 放**稳定的方法与取舍**，不放产品发布新闻；新闻属于判断页的一次性输入。
- `06-工具与项目选型库` 只保留"用过或评估过"的项目；GitHub Star 不作为入选理由。
- `20-业务与产品` 的事实必须能指到官网、后台截图或用户确认；价格与套餐口径以 `03` 为唯一准。
- `30-DSH能力` 记录**本机真实安装**的能力，不写"理论上可以"。
- `40-参考` 默认不读，只在需要举证或追溯时进入；里面的文件冻结，不随版本更新。
