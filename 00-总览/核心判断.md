# 核心判断

> 这页解决一个问题：**如果只记住 14 条结论，应该是哪 14 条。**
> 每条都写成「判断 + 依据 + 动作」。判断会过期，所以都标了时间与适用条件；过期了就改这一页，而不是新增一页。

## A. 技术侧

### 1. AI 系统的瓶颈不在模型，在上下文、工具和验证

模型能力已经过剩，真正决定能不能用的是：喂进去的上下文对不对、工具能不能安全调用、结果怎么验证。
**动作**：做方案先画这三件事；模型选型放在最后，用固定任务集比，不用榜单比。

### 2. 不能验证的自动化是负债，不是资产

Agent 能执行但没有验收标准时，错误会被放大且无人发现。
**动作**：每个自动化环节先定义"怎么知道它做对了"；定义不出来就保留人工确认。

### 3. 单 Agent 优先，多 Agent 只在需要并行或独立审查时上

多 Agent 的收益是角色分工与独立验证，成本是上下文丢失、协调开销和不可复现。
**动作**：能用一个 Agent + 清晰工具集解决的不拆；需要"实现 / 测试 / 审查"分离时才拆。

### 4. RAG 不等于记忆，知识库的门槛是可引用与可更新

普通向量检索只能找到相似文本，解决不了事实冲突、过期、权限和跨会话记忆。
**动作**：企业知识库验收看四条——能否回到原文、能否处理过期与冲突、能否按权限过滤、能否评测召回与引用准确率。

### 5. 选型用自己的任务集，不用公开榜单

榜单衡量的是平均水平，你的业务只关心特定任务上的失败率、成本和延迟。
**动作**：建 20–50 条固定样本，记录正确率 / 成本 / 延迟 / 失败类型；模型换代后重跑同一套。

### 6. 成本是设计出来的，不是省出来的

同一任务在不同模型、上下文长度、缓存策略下成本可差 10 倍以上。
**动作**：模型分层（难任务上强模型、批量任务上小模型）、缓存系统提示与文档、批处理、给每个任务设硬预算上限。

### 7. 安全治理必须前置

Agent 一旦能调工具，提示注入、越权、敏感数据外泄就是默认风险，不是边缘情况。
**动作**：外部内容一律视为不可信输入；网络 / 文件 / 工具分层授权；涉及钱、合同、删除的操作必须人工确认；所有工具调用留审计日志。

## B. 业务侧

### 8. 外贸 AI 的付费点集中在"前端获客"和"后端单证"

获客（找客户、发开发信、内容）直接对应订单，单证（合同、发票、装箱单、信用证）对应人工成本与出错赔偿；中间的 CRM 替换成本最高、意愿最低。
**动作**：新客户先做获客或单证的单点价值证明，不要一上来替换 CRM。

### 9. 产品矩阵必须收敛，否则客户认知会碎掉

对外 6 款产品 + 项目制能力，客户记不住也对比不了；主推超过 2 款时销售话术会自相矛盾。
**动作**：维持「2 主推 + 4 协同 + N 项目制」；协同产品只在客户已认可主推后带入。

### 10. 交付型业务必须把"一单一议"写成流程

Site 的套餐按一单一议是策略，但页面仍挂"基础版/高级版 + 50/200 SKU"就是口径漏洞，会引来比价和扯皮。
**动作**：页面统一改成"按方案报价"，把报价流程（需求→方案→报价→合同）固化下来。

### 11. AI 解决方案不是 SKU，是能力底座 + 垂直方案 + 项目制

客户买的是"这个环节变好"，不是"一个大模型"。把底座（Agent / 知识库 / 工作流）与垂直方案（外贸增长、单证、内容）拆开卖，才能既标准化又接定制。
**动作**：对外讲场景与结果，对内讲底座复用率；项目制交付要能沉淀回产品。

## C. 方法侧

### 12. 知识库只沉淀"能改变判断"的内容

链接不是知识，新闻不是知识；能改变下次决策的结论、方法、边界才是。
**动作**：新材料先问"它改变了哪条判断"；答不上来就只留链接，不进正文。

### 13. 自动化先留人工回路，再谈无人化

一步到位的无人流程在真实业务里几乎都会因异常分支失败。
**动作**：先做"AI 起草 + 人确认"，统计人工修改率；修改率降到阈值内再逐步放开。

### 14. 一切结论带日期与来源

模型、价格、平台政策以季度为单位变化；没标时间的结论会变成负债。
**动作**：正文用「截至 2026-11」，来源给可点击链接；超过半年的价格类结论必须复核。
